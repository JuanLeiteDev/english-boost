English Boost: guia completo

O que foi construído, como usar no dia a dia, o que está por trás (Docker, autenticação do Claude e do Codex) e como pôr tudo a correr noutro computador, em Linux ou Windows.

Parte 1 · Usar

Em resumo

Um projeto Git que é, ao mesmo tempo, um plano de estudo (de A2 a B1 sólido até 01/02/2027), uma equipa de tutores de IA (skills para o Claude e o Codex) e uma app web onde estudas todos os dias.

📅

Plano fundamentado

10 semanas, 45 unidades de gramática e 4 checkpoints, com base em estudos verificados.

🧠

21 skills

18 externas e 3 criadas para ti: planeador diário, examinador CEFR e coach de speaking.

💬

App de estudo

Chat com o Claude ou o Codex, um painel que abre o material e exercícios com correção automática.

🔑

Sem API

Os agentes usam as tuas subscrições (Claude e ChatGPT), sem chaves de API nem custos extra.

Arrancar a app

docker compose up -d     # liga (e fica ligada; arranca sozinha com o Docker)
docker compose down      # desliga

Abre http://127.0.0.1:8765. Funciona igual em Linux, macOS e Windows.

./estudar.sh             # abre o browser em http://127.0.0.1:8765 · Ctrl+C para sair
estudar.bat              # duplo-clique ou na PowerShell · abre http://127.0.0.1:8765
Usa uma variante de cada vez. As duas ocupam a porta 8765.

Um dia de estudo

  1. Abre a app e clica no cartão azul (Estudo de hoje, ou Checkpoint/Revisão semanal nesses dias). O painel Hoje abre com os 4 blocos e o tutor guia-te.
  2. Liga o cronómetro ▶ no painel.
  3. Vocabulário (8′): revisão SRS (Anki ou o botão Rever).
  4. Gramática (22′): clica Abrir, responde dentro da unidade, carrega em Corrigir e depois em Guardar. Se falhares, usa Explicar erros.
  5. Listening (15′): o Abrir leva-te ao recurso. Ciclo: prever, ouvir, verificar, ler a transcrição, fazer shadowing.
  6. Output (15′): Praticar. Speaking: falas (🎤) ou escreves para o coach. Escrita: escreves e o examinador corrige.
  7. Terminar sessão: confirma os números. Fica registado no log, na espinha de gramática e no dashboard.
  8. Progresso → Guardar no Git: faz o commit e envia para o GitHub.

Parte 2 · Técnico

Arquitetura

Não há base de dados nem nuvem: tudo são ficheiros de texto no projeto, versionados no Git. A app é uma camada fina entre o browser, esses ficheiros e os CLIs dos agentes.

PeçaFicheiroDetalhe
Servidorapp/server.pyUsa o ThreadingHTTPServer do Python, sem dependências. Serve a página e uma API JSON, lança os CLIs e transmite as respostas.
Interfaceapp/static/*.js|cssJavaScript simples, sem build. Renderizador de markdown próprio (md.js), funciona offline.
Leitura dos dadosscripts/build_dashboard.pyLê as tabelas markdown (espinha, log, erros, semanas). A app reutiliza estas funções.
Instruções dos agentesAGENTS.md + CLAUDE.mdO Codex lê o AGENTS.md; o CLAUDE.md importa-o (@AGENTS.md).
Skills.agents/skills/Ficheiros reais aqui. O .claude/skills é um link para esta pasta.

Como funciona o chat

  1. Escreves uma mensagem. O browser faz POST /api/chat/send com o token da sessão.
  2. O servidor lança o CLI em modo não interativo, na pasta do projeto: 
    # Claude (1.ª mensagem; depois acrescenta --resume <sessão>)
claude -p "mensagem" --output-format stream-json --verbose --include-partial-messages \
  --permission-mode acceptEdits --allowedTools "Read,Write,Edit,Skill,WebSearch,…" \
  --append-system-prompt "contexto da app"

# Codex (1.ª mensagem; depois: codex exec resume <sessão> …)
codex exec --json -m gpt-6-sol -s workspace-write "contexto da app + mensagem"
  3. O CLI emite eventos JSON linha a linha. O servidor converte-os em {"t":"text"|"tool"|"error"|"done"} e envia-os ao browser em streaming (NDJSON). Aparecem o texto e os passos ("Ler plan/…", "Skill: …").
  4. O ID da sessão fica em app/state/chats.json, e por isso a conversa continua (--resume / exec resume). O ➕ apaga-o e começa do zero.
  5. Se a resposta tiver marcadores como [[abrir:P1-02]], [[abrir:hoje]], [[abrir:doc:…]] ou [[abrir:url:…]], a interface abre esse conteúdo no painel. É assim que "estudo de hoje" abre o material sozinho.
Correção automática dos exercícios

Os gabaritos (materials/grammar/answers/) só são pedidos ao servidor quando carregas em Corrigir. A comparação normaliza as respostas: maiúsculas, pontuação, contrações (don't = do not), alternativas separadas por /, palavras opcionais entre parênteses e respostas parciais com …. Testada com os 99 itens das 5 primeiras unidades. Se uma resposta certa não for reconhecida, está certo corrige a nota. Guardar grava a % na espinha e as respostas em progress/exercises/.

Permissões dos agentes dentro da app

Claude: acceptEdits permite editar ficheiros do projeto sem perguntar. Os comandos de terminal estão limitados a uma lista (date, ls, cat, git status/log/diff, o dashboard…) e o resto é recusado. Codex: sandbox workspace-write (escreve só no projeto). Em Docker, o próprio contentor faz de sandbox (ver Docker).

Autenticação: sem API, com as tuas contas

Os CLIs oficiais aceitam login com a conta de subscrição (OAuth), e não só com uma chave de API. A app nunca vê nem guarda as tuas credenciais: limita-se a lançar o CLI, e o CLI autentica-se sozinho. O uso conta para os limites da tua subscrição, como se usasses o Claude Code ou o Codex diretamente.

Nativo (Linux/Windows)Docker
ClaudeUsa o login que fizeste na extensão Claude Code do VS Code (o CLI vem com a extensão). Credenciais em ~/.claude/.credentials.json. A app encontra o binário em ~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/.claude auth login: abres um link, autorizas e colas o código. Fica guardado no volume claude-home (CLAUDE_CONFIG_DIR).
CodexUsa o login da app Codex/ChatGPT (~/.codex/auth.json). No Linux, o CLI vem com a app (/usr/lib/chatgpt/resources/codex).codex login --device-auth: abres um link, introduzes um código e entras com a conta ChatGPT. Fica no volume codex-home.
GitHubgh auth login (código no browser). O token fica no keyring do sistema. Conta: JuanLeiteDev.Igual, guardado no volume gh-config. É opcional: só serve para o push do botão.
O login em Docker é separado do login nativo. O contentor não vê as credenciais do teu PC, e isso é intencional: assim tudo funciona igual em qualquer sistema e as tuas credenciais nunca saem do seu sítio. Faz-se uma vez por dispositivo: docker compose run --rm app login.

Docker por dentro

Um contentor é um Linux mínimo e isolado que corre dentro do teu sistema. No Windows e no macOS, o Docker Desktop executa-o numa pequena máquina virtual Linux (no Windows, via WSL 2). Por isso a app corre exatamente no mesmo ambiente em todos os sistemas.

O serviço (compose.yaml)

ports:   "127.0.0.1:8765:8765"            # só acessível a partir deste PC
volumes: .:/workspace                      # o projeto, do teu disco (não é copiado)
         claude-home  codex-home  gh-config  # logins persistentes
restart: unless-stopped                    # volta a ligar sozinha
env:     CODEX_SANDBOX=danger-full-access  # a sandbox é o contentor

O arranque (docker/entrypoint.sh)

ComandoFaz

Também configura o Git (safe.directory, nome e email do .env) e, se o link .claude/skills não funcionar (clone em Windows), liga as skills ao nível do utilizador do Claude dentro do contentor.

Porque é que o Codex corre sem a sandbox dele no Docker?

A sandbox do Codex em Linux usa funcionalidades do kernel (namespaces, Landlock/seccomp) que um contentor normal não deixa usar. A prática habitual é delegar o isolamento no contentor: o Codex só vê /workspace (o projeto) e as suas próprias credenciais. Não vê o resto do teu disco nem o teu sistema.

Parte 3 · Outro PC

Instalar noutro PC

  1. Instala o Docker. Windows/macOS: Docker Desktop (no Windows com WSL 2, que o instalador ativa). Linux: Docker Engine e depois sudo usermod -aG docker $USER; termina a sessão e volta a entrar.
  2. Clona o projeto e constrói a imagem (3–5 min na 1.ª vez): 
    git clone https://github.com/JuanLeiteDev/english-boost.git
cd english-boost
cp .env.example .env          # opcional: TZ, porta, nome/email dos commits
docker compose build
  3. Faz login uma vez (Claude, Codex e GitHub opcional): 
    docker compose run --rm app login
  4. Liga a app e abre http://127.0.0.1:8765: 
    docker compose up -d
No Windows usa a PowerShell ou o Terminal: os comandos são os mesmos. O Git for Windows é preciso só para o git clone.

  2. Agentes (pelo menos um):
    Claude: extensão Claude Code no VS Code com login feito, ou curl -fsSL https://claude.ai/install.sh | bash e depois claude para entrar.
    Codex: app Codex/ChatGPT, ou npm i -g @openai/codex e codex login.
  3. Configura e arranca:

O Windows nativo foi preparado mas não testado (não havia Windows disponível). Se algo falhar, usa o Docker: é o caminho testado e igual em todo o lado.

Testes automáticos

python3 -m unittest discover -s tests -t .   # ~5 s · agentes simulados, sem rede

Os agentes são substituídos por dois scripts (tests/fake_agents/) que emitem os mesmos eventos JSON do Claude e do Codex. Assim testa-se o chat inteiro (streaming, retoma de sessão, parar, timeout) sem gastar a subscrição. O GitHub Actions corre a bateria em Linux, Windows e macOS, e constrói e testa a imagem Docker em cada push.

Problemas comuns

permission denied … docker.sock (Linux)

Corre sudo usermod -aG docker $USER e termina a sessão. Até lá, usa o prefixo sg docker -c "docker compose …".

"Claude/Codex não encontrado" na app

Docker: docker compose run --rm app status e, se for preciso, login. Nativo: ⚙ Definições, onde indicas o caminho do executável (no Windows tem de ser um .exe; os atalhos .cmd do npm não servem porque não aceitam mensagens com várias linhas).

O agente responde com erro de login ou sessão expirada

Docker: docker compose run --rm app login. Nativo: abre o Claude Code no VS Code ou a app Codex e volta a entrar.

Porta 8765 ocupada

Tens a versão nativa e a Docker ligadas ao mesmo tempo. Desliga uma, ou muda a porta: HOST_PORT=8766 no .env (Docker) ou ./estudar.sh --port 8766.

O Claude não encontra as skills (Windows nativo)

O link .claude/skills chegou como ficheiro de texto. Corre scripts\setup-windows.ps1, que cria uma junção sem precisar de administrador.

Atualizar as versões do Claude ou do Codex no Docker

Muda CODEX_VERSION / GH_VERSION em docker/Dockerfile e corre docker compose build --no-cache && docker compose up -d. Os logins mantêm-se, porque estão nos volumes.

O Codex diz que "a ferramenta de shell falhou" (Docker)

Falta o codex-code-mode-host na imagem. Se alterares a versão do Codex, confirma que a release tem esse ficheiro para a tua arquitetura e reconstrói: docker compose build && docker compose up -d.

O "hoje" da app está errado

Fuso horário: TZ=Europe/Lisbon (ou Europe/Brussels quando estiveres na Bélgica) no .env, e depois docker compose up -d.

Limites conhecidos

  • A IA não ouve a tua pronúncia: trabalha a partir do ditado. As palavras mal reconhecidas servem de pista (p. ex. "tree" quando querias dizer "three").
  • O microfone só funciona no Chrome ou no Edge.
  • A app é para este PC (localhost). Não está pensada para abrir no telemóvel pela rede.
  • As unidades de gramática da semana 2 em diante são criadas pelo daily-study-planner na revisão semanal. Até lá aparecem esbatidas.
  • Windows nativo não testado. O Docker foi construído e testado neste Linux, com login e conversa real com o Claude e com o Codex dentro do contentor.
